2. Схема наследования
```text
InventoryItem (abstract)
├── Transport (abstract)
│   ├── Bike
│   ├── EBike ────────────┐ (multiple)
│   ├── ElectricScooter ──┐ (multiple)
│   └── Deltaplan         │
└── Thing (abstract)      │
    ├── Helmet            │
    └── DockStation ──────┤ (multiple)
                          │
EnergyConsumer (abstract) ┘
```
3. unique_ptr создается при добавлении нового объекта, и преобразуется при передаче в fleet. Именно он, так как на этапе создания и проверки объектом не должен никто лишний владеть, у него должен быть один хозяин, иначе при непрохождении проверки в ServiceCenter может получится, что объект останется жив. shared_ptr используется для хранения в парке, так как надо уметь делиться объектами. weak_ptr реализован для фокуса на витрине, так как мы должны только наблюдать за объектом, а не получать владение, чтобы можно было удалить через remove.

4. Все исключения описаны в Errors.hpp. Чаще всего бросаются исключения ParseError - если введена неверная комманда, InputError - если к комманде приложены неверные значения переменных, InspectionError - если объект не прошел проверку в ServiceCenter, UnexpectedIdError - если пытаемся сделать remove для несуществующего ID. FleetError - базовый класс исключений, от него наследуются все остальные исключения. Исключений больше, чем я описал здесь, но оставшиеся в основном кидаются при некорректных значениях параметров.

5. Добавлен шаблон RegJournal для ServiceCenter, ServiceCenter хранит три журнала - для добавленного транспорта, для добавленных вещей, для забракованных предметов. Соответсвенно, для первого журнала указатель на класс Transport, для второго журнала указатель на класс Thing, для третьего журнала специализация для string, так как забракованные предметы удаляются, поэтому оставляем только воспоминание. 

6. В креативной части добавлен дельтаплан (add deltaplan id name score height quality). Также добавлены функции medium_novice_score - средний рейтинг новичков, max_height - максимальная высота среди всех средств транпорта, так как в воздухе летают толлько дельтапланы, то соотвественно, если их нет ответ 0, если они есть - максимальная высота среди дельтапланов. Еще у журналов в ServiceCenter есть ограничение на 100 записей, поэтому если оно достигается, то нельзя добавлять новые предметы (какие -  в зависимости от того, какой журнал переполнен) - кидается исключение JournalOverflowError. Чтобы продолжить добавлять элементы надо очистить журнал, для каждого журнаале сть отдельная функция очистки: clean vehicles, clean things, clean notes - после этого все записи сбрасываются и ServiceCenter снова позволяет добавлять элементы. Также решено проверять на пригодность не только Transport, но и Things, так как они тоже могут быть сломаны.
